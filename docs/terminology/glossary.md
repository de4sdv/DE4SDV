# Glossary

- **SDV** — Software-Defined Vehicle; a vehicle whose behavior and value are
  increasingly defined by software capabilities.
- **MBSE** — Model-Based Systems Engineering.
- **SysML v2** — Next-generation Systems Modeling Language and related API
  concepts.
- **MBPLE** — Model-Based Product Line Engineering.
- **Product line** — Family of similar products with managed variation among
  member products.
- **Member product** — Product belonging to a product line.
- **Feature** — Distinguishing characteristic of a member product in a product
  line. In DE4SDV, a feature expresses variability among member products.
- **Common capability** — Capability or characteristic present in all member
  products. It can be modeled and traced, but should not be treated as a feature
  in feature-based PLE.
- **Feature model** — Model of product-line feature options, constraints, and
  valid feature selections.
- **Feature catalogue** — Model of available feature options and feature
  constraints across the product line.
- **Bill-of-features** — Specification of the selected features for a member
  product.
- **Feature configuration** — A selected set of features defining a product
  variant or member-product configuration.
- **Feature constraint** — Formal relationship among features that valid member
  products must satisfy, such as requires or excludes.
- **Shared asset** — Reusable engineering artifact used across product variants.
- **Shared asset superset** — Shared asset representation containing all content
  needed by any member product in the product line.
- **Variation point** — Location in a shared asset superset where content is
  configured according to feature selections.
- **Product asset instance** — Member-product-specific instance produced from
  shared asset supersets and feature selections.
- **Product model** — Variant-specific system model assembled from shared assets
  and configuration decisions.
- **Ontology** — Explicit model of domain concepts, relationships, constraints,
  and intended semantics.
- **Domain-specific language** — Project-specific language or vocabulary used to
  express DE4SDV concepts, constraints, and traceability in a consistent way.
- **Ontology diagram** — Human-readable view of ontology concepts and
  relationships. Useful for review, but not necessarily the semantic source of
  truth.
- **Evidence artifact** — Planned or actual artifact supporting verification,
  validation, assurance, release, or certification claims.
- **Digital thread** — Traceability chain across lifecycle artifacts and
  decisions.
- **Digital twin** — Digital representation synchronized with real-world system
  data and assumptions.
- **OSLC** — Open Services for Lifecycle Collaboration.
- **FMU** — Functional Mock-up Unit.
- **FMI** — Functional Mock-up Interface.
- **SSP** — System Structure and Parameterization.
- **Continuous homologation** — Continuous preparation and management of
  compliance evidence throughout engineering changes.
