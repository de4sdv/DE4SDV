# Governance

This is an initial lightweight governance model.

## Roles

- **User:** Uses project assets and gives feedback.
- **Contributor:** Submits documentation, models, code, tests, analysis, issues, or reviews.
- **Maintainer:** Reviews and merges contributions, triages issues, and supports releases.
- **Steering group:** Future role for roadmap, governance changes, and cross-domain alignment.

## Decision making

- Prefer consensus in public issues and pull requests.
- Technical decisions should be documented as ADRs in `docs/architecture-decisions/`.
- Safety, security, and compliance decisions require explicit evidence and reviewer attention.

## Becoming a maintainer

Maintainer nomination criteria:

- Sustained high-quality contributions
- Constructive collaboration
- Understanding of project goals and boundaries
- Responsible handling of safety/security/compliance topics

## Governance changes

Governance changes require a pull request, public discussion, and approval from current maintainers.
